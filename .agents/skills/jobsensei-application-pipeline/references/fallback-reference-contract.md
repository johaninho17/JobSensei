# Fallback Reference Contract

`data/fallback-references/` contains example artifacts, not career evidence.

Read it only after a deterministic validation failure in a public application artifact, or when the user explicitly asks for an example comparison. Select the closest artifact type: resume examples for resume structure, cover letters for letter structure and tone, and evaluation or match reports for report organization.

Never use fallback references to prove or support a candidate fact. Do not copy their employers, dates, titles, metrics, technologies, claims, motivation, job details, or provenance. Do not treat them as templates for factual content. They may inform only:

- section ordering and organization
- content density and length
- paragraph shape and tone
- presentation choices

After consulting a fallback reference, regenerate once using the active job, approved career evidence, and the public/private artifact contract. Re-run validation. If the artifact still fails, stop and report the failed constraint; do not keep consulting examples or broaden source discovery.
